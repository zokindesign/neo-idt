## 一、区分原则

### 1.1 为什么需要区分能力与偏好？

传统包容性设计混淆了"能力条件"与"偏好倾向"，导致两个问题：

| 混淆的后果 | 能力因素被误视 | 偏好因素被误视 |
|-----------|--------------|--------------|
| **采用"补偿" mindset** | ✅ 适当（需要补偿） | ❌ 不适当（偏好不是缺陷） |
| **采用"适配" mindset** | ❌ 不足（需要主动提供方案） | ✅ 过度（只需提供选择）|
| **设计响应错误** | 可能只提供单一最优方案 | 可能提供过多选项导致决策疲劳 |

**正确区分是正确设计响应的前提。**

### 1.2 定义

#### **能力因素 (Ability/Capacity Factors)**

- **本质**：客观的生理、认知或环境条件限制
- **可变性**：相对稳定（非自愿改变困难）
- **社会认知**：常被视为"缺陷"或"障碍"
- **用户意图**：用户希望**克服或绕过**的限制
- **设计目标**：**提供替代方案**，确保功能可达性

**示例**：
- 视力障碍 → 需要听觉或触觉替代通道（TTS、盲文）
- 运动能力受限 → 需要简化操作、语音控制、大点击区域
- 认知处理速度慢 → 需要更长的响应时间、分步引导
- 网络带宽低 → 需要离线模式、低分辨率选项

#### **偏好因素 (Preference Factors)**

- **本质**：主观的选择倾向与舒适度偏好
- **可变性**：可能随情境、心情、阶段变化
- **社会认知**：应视为"差异"而非"缺陷"
- **用户意图**：希望**按自己的方式做事**
- **设计目标**：**提供选择空间**，让用户自行配置

**示例**：
- 信息密度偏好 → 提供精简视图与详细仪表板两种模式
- 视觉风格偏好 → 提供深色/浅色/自定义主题
- 控制感偏好 → 全自动 vs 手动控制选项
- 社交压力承受度 → 隐身模式 vs 实名模式

## 二、区分判断流程

### 2.1 判断问询表

当识别到一个新因素时，依次回答以下问题：

| 问询问题 | 如果是 → 分类 | 举例 |
|---------|-------------|------|
| 这是否是客观物理/生理限制？ | 能力因素 | 色盲、听力损失、肌无力 |
| 用户是否难以**自主改变**此状态？ | 能力因素 | 无法短期提高视力、无法消除听力障碍 |
| 这是否反映**主观舒适度**或**价值取向**？ | 偏好因素 | 喜欢简洁 vs 丰富、重视效率 vs 体验 |
| 用户是否可能在不同情境下**切换选择**？ | 偏好因素 | 工作时需高效、休息时需放松 |
| 如果提供选项，用户是否**都会选同一个**？ | 可能是能力因素 | 色盲用户永远需要高对比度 |
| 这关乎**功能可达性**还是**体验优化**？ | 功能→能力；体验→偏好 | 文字转语音是可达性，动效密度是体验 |

### 2.2 边界案例处理

某些因素存在**能力与偏好的混合属性**，需要细化：

| 混合因素 | 能力成分 | 偏好成分 | 处理建议 |
|---------|---------|---------|---------|
| 感觉处理能力（原"感觉整合"） | 神经功能状态（过敏/迟钝） | 环境刺激的舒适阈值 | 维度一归为能力，提供环境控制选项；维度四的环境刺激偏好留作纯偏好 |
| 时间压力 | 任务固有时间约束（外部） | 个人节奏偏好（内部） | 任务时间压力作为任务因素（能力），使用节奏偏好作为偏好因素 |
| 认知负荷 | 任务复杂度与用户能力差距（客观） | 引导程度偏好（主观） | 负荷本身是能力因素，引导偏好是偏好因素，两者通过 DEP-001 关联 |

## 三、设计响应模式

### 3.1 能力因素响应：提供替代方案

**核心逻辑**：当主要交互通道不可用时，提供功能等效的替代通道。

**设计模式**：
- **多通道冗余**：视觉 + 听觉 + 触觉信息呈现
- **操作方式多样化**：点击、拖拽、键盘快捷键、语音命令、手势
- **时间灵活性**：延长响应时间、允许分步完成、保存进度
- **复杂度可调**：简化模式、专家模式、渐进披露

**示例对照表**：

| 能力因素 | 替代方案示例 |
|---------|-------------|
| 视力障碍 | 屏幕阅读器支持、高对比度主题、盲文输出、非颜色编码（图案/纹理） |
| 运动障碍 | 语音控制、大点击区域、头部追踪、眼动控制、开关控制 |
| 听力障碍 | 文字字幕、视觉提示、振动反馈、手语视频 |
| 认知处理慢 | 分步引导、可重复操作、决策辅助、简化界面 |
| 语言障碍 | 多语言支持、图标辅助、简单语言、机器翻译 |

**⚠️ 重要原则**：
- 替代方案必须在功能上等效（不是降级）
- 用户应能**轻松切换**，无需额外配置（默认提供）
- 不能要求用户"证明自己有需求"才能获得替代方案

### 3.2 偏好因素响应：提供选择空间

**核心逻辑**：用户在"如何工作"上有不同倾向，设计应允许个性化配置，但不应强制任何选择。

**设计模式**：
- **可配置选项**：主题、布局、通知频率、默认行为
- **自适应显隐**：根据行为推测偏好，但允许覆盖
- **光谱调节**：滑动条而非二选一（如自动化程度滑块）
- **预设档位**：新手/专家、简洁/丰富、严肃/轻松

**示例对照表**：

| 偏好因素 | 选择空间示例 |
|---------|-------------|
| 信息密度偏好 | 精简视图（核心信息） ↔ 仪表板视图（全面数据） |
| 引导程度偏好 | 自主探索模式 ↔ 全程向导模式 ↔ 上下文帮助 |
| 视觉风格偏好 | 扁平暗色 ↔ 明亮拟物 ↔ 自定义主题编辑器 |
| 控制感偏好 | 全手动控制 ↔ 建议模式 ↔ 全自动执行 |
| 社交压力承受度 | 隐身/仅自己可见 ↔ 实名/社交可见 ↔ 专业身份公开 |
| 时间投入模式 | 碎片化快操模式 ↔ 沉浸深度模式 |

**⚠️ 重要原则**：
- 选择应是**平权的**——无"默认正确"选项，或默认应是最通用/安全的
- 避免**选择悖论**——选项数量适中（3-7个），可分层级
- **无惩罚的切换**——用户可随时更改，且历史数据/进度不受影响

## 四、混合因素的细化处理

### 4.1 感觉处理能力 vs. 环境刺激偏好

**感觉处理能力**（维度一，能力因素）：
- 神经生理层面的过敏或迟钝
- 用户难以自主改变
- 设计响应：**提供环境控制**（亮度调节、降噪、屏蔽特定频率声音）

**环境刺激偏好**（维度四，偏好因素）：
- 主观上对光、声、气味的舒适度偏好
- 可能随情境变化
- 设计响应：**提供环境预设档位**（专注模式、放松模式、娱乐模式）

**区分技巧**：
- 问"这是病理性的吗？" → 是 → 能力；否 → 偏好
- 问"用户是否愿意改变？" → 无法改变 → 能力；可改变 → 偏好

### 4.2 时间压力 vs. 使用节奏偏好

**时间压力**（任务维度，能力因素）：
- 任务固有时间约束（如"5分钟内完成"）
- 外部施加，用户无法控制
- 设计响应：**加速流程、快速路径、减少决策**

**使用节奏偏好**（偏好维度，偏好因素）：
- 用户偏好的使用模式（碎片化 vs 沉浸）
- 主观习惯，用户可能切换
- 设计响应：**提供节奏适配模式**（快速操作模式 vs 深度体验模式）

### 4.3 认知负荷 vs. 引导程度偏好

**认知负荷**（任务维度，能力因素）：
- 任务带给用户的认知负担（复杂度、信息量）
- 客观测量指标：错误率、完成时间、注意力分散次数
- 设计响应：**降低负荷**（简化、分步、自动化）

**引导程度偏好**（偏好维度，偏好因素）：
- 用户希望系统介入辅助的程度
- 主观倾向，有人喜欢探索，有人喜欢指导
- 设计响应：**提供引导强度调节**（无引导、轻提示、全过程向导）

**规则关联**：`DEP-001`表明引导程度偏好的有效性依赖于认知负荷状态——高负荷时引导需求上升。

## 五、设计决策检查清单

当设计一个新功能或优化时，使用此清单确保覆盖能力与偏好：

### 5.1 能力因素检查

- [ ] **可见性**：视力障碍用户能否获取所有关键信息？（非颜色编码、屏幕阅读器支持）
- [ ] **可听性**：听力障碍用户能否获取所有音频信息？（字幕、视觉替代）
- [ ] **可操作性**：运动障碍用户能否完成所有操作？（键盘、语音、大点击区域）
- [ ] **可理解性**：认知障碍用户能否理解内容？（简单语言、分步、重复）
- [ ] **时间宽容**：时间压力用户能否从容完成？（延长响应时间、保存进度）
- [ ] **技术可及**：低技术条件用户能否使用？（低带宽模式、低配设备适配）

### 5.2 偏好因素检查

- [ ] **信息密度**：是否提供精简与详细两种模式？
- [ ] **视觉风格**：是否提供主题切换或自定义选项？
- [ ] **引导强度**：是否允许用户调节引导程度？
- [ ] **自动化程度**：是否允许用户选择全手动/半自动/全自动？
- [ ] **社交暴露**：是否允许用户控制个人信息可见度？
- [ ] **反馈密度**：是否允许用户选择实时/总结性反馈？

## 六、常见错误与陷阱

| 错误 | 表现 | 纠正 |
|------|------|------|
| 将偏好误判为能力 | "老年人喜欢大字体" → 视为能力缺陷 | 大字体应为**选择**而非**强制**；提供字体调节滑块 |
| 将能力误判为偏好 | "用户只是不习惯" → 忽视无障碍需求 | 能力因素必须**默认支持**，不能依赖用户配置 |
| 补偿变成降级 | 视频语音描述"够用了"——替代方案质量低 | 替代方案必须**功能等效**，不能是"简化版" |
| 选择变成负担 | 提供20种主题，用户不知如何选 | 提供**预设档位** + **自定义高级选项**；默认合理选项 |
| 忽略混合因素 | 感觉处理能力只做偏好处理 | 明确区分能力成分（提供控制）与偏好成分（提供预设） |

## 七、验证方法

如何验证一个因素的分类正确？

1. **用户测试**：观察目标用户是否使用你提供的选项；如果是替代方案，用户是否真的能完成任务
2. **专家评审**：邀请无障碍专家、UX研究员评估分类合理性
3. **数据指标**：功能使用率、配置选择分布、任务完成率与时间对比
4. **第三方法规对照**：与WCAG、Section 508等标准对照，确认能力因素是否全面覆盖
