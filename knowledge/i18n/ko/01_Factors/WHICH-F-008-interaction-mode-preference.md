## 기본 정의
사용자가 선호하는 시스템과의 상호작용 방식으로, 직접 조작(클릭, 드래그) vs 명령형(지시 입력), 제스처, 음성, 키보드 단축키 등이 있다.

## 왜 중요한가
- 사용자마다 상호작용 모드에 대한 숙련도와 편안함의 차이가 크다
- 과제 상황도 최적의 상호작용 모드에 영향을 미친다(예: 운전 중에는 음성이 적합)
- 다양한 상호작용 모드를 제공하면 효율과 접근성을 높일 수 있다

## 정량화 기준
- **사용 빈도**: 각 모드의 실제 사용 비율
- **오류율**: 모드별 조작 오류율
- **과제 완수 시간**: 서로 다른 모드가 같은 과제를 완수하는 평균 시간
- **학습 곡선**: 새 모드를 익히는 데 필요한 시간

## 설계 가이드
- 여러 상호작용 방식을 동시에 지원한다(마우스, 터치, 키보드, 음성)
- 사용자가 기본 상호작용 모드를 설정할 수 있게 한다
- 전환을 강제하지 않는다(예: 터치 스크린 기기에서도 오른쪽 버튼 메뉴 유지)
- 모드 전환 단축 기능을 제공한다

## 영역별 발현
| 영역 | 모드 예 |
|------|----------|
| **데스크톱 소프트웨어** | 메뉴 내비게이션, 단축키, 명령줄, 드래그 |
| **모바일 앱** | 터치 제스처, 음성 입력, 물리 버튼 |
| **스마트 홈** | 앱 제어, 음성 비서, 물리 스위치, 자동화 시나리오 |
| **게임** | 키보드·마우스, 게임패드, 모션, 터치 스크린 |

## 관련 표준
- 통일된 표준 없음; 플랫폼 규범(iOS HIG, Material Design)을 따를 필요가 있다
