## 기본 정의
작업이 일시정지·중단을 허용하는지, 그리고 중단 후 복원의 용이성 요구. 지속성과 관련되지만 '중단이 발생했을 때'의 사용자 경험에 초점을 둔다.

## 왜 중요한가
- 현실 환경에서 사용자는 전화, 알림, 타인에 의해 자주 중단된다
- 중단 허용도가 낮은 작업에는 방해 차단 설계가 필요하다
- 중단 후에는 상태가 손실되거나 오류(오조작 등)가 발생하기 쉽다

## 정량화 기준
- **중단 복귀 시간**: 사용자가 중단에서 작업 상태로 돌아오는 평균 소요 시간
- **중단 비용**: 중단으로 인한 데이터 손실 또는 진행 후퇴의 정도
- **방해 차단 요구**: 사용자가 방해 금지 모드를 사용하는 빈도와 강도
- **비동기 지원**: 작업이 '먼저 시작하고 나중에 완료' 방식을 지원하는지(예약, 대기열 등)

## 설계 가이드
- '저장되지 않은 변경 사항'과 복원 옵션을 명확히 표시한다
- '나중에 처리' 메커니즘을 제공한다(할 일로 저장, 알림 리마인더)
- 사용자가 능동적으로 '집중 모드'를 설정할 수 있게 한다(긴급하지 않은 알림 차단)
- 중단 지점 설계: 작업을 덩어리로 나누어 각 덩어리가 상대적으로 독립적이게 한다

## 영역별 발현
| 영역 | 중단 처리 |
|------|----------|
| **양식/설문** | 임시 저장, 여러 번에 나누어 작성 허용 |
| **회의/라이브** | 녹화 다시보기, 노트에 타임스탬프 동기화 |
| **거래 흐름** | 장바구니 유지, 주문 임시 저장 |
| **창작 도구** | 다단계 되돌리기, 스냅샷, 분기 이력 |

## 관련 표준
- 범용 UX 패턴: 자동 저장, 임시 저장, 오프라인 대기열
