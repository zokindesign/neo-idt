## 기본 정의
사용자가 긴급 상황(예: 의료 응급, 화재, 자연재해, 안전 위협)에서 제품이나 서비스를 사용하는 능력과 특수 요구.

## 왜 중요한가
- 긴급 상황에서는 사용자의 인지 부하가 급증하고 시간이 촉박하며 조작 능력이 제한된다
- 일상적인 상호작용 흐름은 빠른 응답 요구를 충족하지 못할 수 있다
- 포용적 설계는 취약한 상태에서의 접근성을 반드시 고려해야 한다

## 정량화 기준
- **활성화 시간**: 긴급 상태 인식에서 구조 요청 개시까지의 시간 창
- **조작 복잡도**: 긴급 호출에 필요한 최소 조작 수(이상적으로 1단계)
- **보조 기능**: 음성 트리거, 버튼 트리거, 환경 센서 자동 트리거가 가능한지
- **오류 관용 기제**: 오조작 후 취소 또는 되돌리기 능력(오조작으로 실제 구조 요청이 지연되는 것을 방지)

## 설계 가이드
- 원클릭 구조 요청(SOS) 기능을 제공하고 항상 접근 가능하게 한다(잠금 화면에서도)
- 긴급 절차를 극도로 단순화하고 다중 확인을 피한다(단, 오조작 취소는 제공한다)
- 다중 채널 트리거(소리, 제스처, 버튼, 자동 모니터링)를 지원한다
- 명확한 긴급 상태 확인과 피드백을 제공한다(구조 요청 완료, 위치 공유)
- 사용자가 당황한 상태일 수 있으므로 설계는 포카요케(실수 방지)여야 한다

## 영역별 발현
| 영역 | 긴급 기능 예시 |
|------|--------------|
| **모바일 기기** | 잠금 화면 긴급 호출, 낙상 감지 자동 구조 요청 |
| **자동차** | 긴급 제동, 원클릭 구조 호출 |
| **스마트홈** | 화재/가스 자동 경보 및 긴급 연락처 통지 |
| **웨어러블 기기** | 의료 긴급 버튼, 심박 이상 경보 |

## 관련 표준
- 각지의 긴급 호출 서비스 표준(예: 110/120/911)
- 국제 무장애 표준에서의 긴급 통신 요구(예: TIA-603)
- 제품 안전 인증 요구
